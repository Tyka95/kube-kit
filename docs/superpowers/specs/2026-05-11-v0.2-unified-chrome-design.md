# KubeKit v0.2 — Unified Chrome, Semantic Palette, Single Picker

**Status:** Draft for review
**Scope:** Phases 2-3 of the KubeKit v0.2 work. P1 (AWS session state + RDS discovery) is already implemented on this branch; v0.2 builds the visible redesign on top of it.
**Date:** 2026-05-11
**Branch:** `feat/auth-state-and-rds-discovery`

## Problem

P1 fixed the *state* underneath the UI (auth correctness, mismatch detection, no-silent-failure discovery). The chrome itself is still amateurish:

- A 16-symbol morphing icon at the top-left looks like a screensaver. k9s, lazygit, gh-dash — none animate.
- Two parallel picker paradigms: KubeKit's own `choose_menu` (with shimmer + filter) in the main menu, `gum choose`/`gum filter` (no animation, different keybindings) in every sub-flow. The user learns one mental model and then loses it.
- Colors are named positionally (`C_CYAN_B`, `C_LCYAN`, `C_DIM`). No discipline — palette drift over time, "what does C_CYAN_B even mean" semantically.
- Footer carries identity ("production-eks │ default │ stage ✓ ..."). Header carries decoration. This is backwards: per k9s/lazygit convention, *header carries state, footer carries affordances*.
- No context-sensitive keybinding hints. Each screen has the same global `← ↓ ↑ → navigate • enter submit` and nothing else.
- Bash-drawn double bars (`═`, `─`) are visually heavy; rounded `╭ ╮ ╰ ╯` corners read as modern.

## Goals

1. One picker paradigm everywhere — `gum choose` / `gum filter` calls go away. `gum confirm` and `gum input` stay (they're modal, no UX mismatch).
2. Header = state + contextual key hints. Footer = current-screen affordances + position. Breadcrumb between them.
3. Six semantic color tokens replace every existing color constant in the codebase.
4. Single rounded-border style applied consistently around the chrome.
5. No morphing icon. Static sigil only.
6. Discoverable keybindings: each screen surfaces 3-5 context-sensitive keys in the header, the rest live behind `?`.
7. Shared `/` (filter) and `:` (command) input zone, like k9s.

## Non-goals

- Replacing `gum` as a dependency. We keep `gum confirm` and `gum input`.
- Multi-panel split-pane layouts (lazygit's 5-panel model). KubeKit stays single-pane; complexity isn't justified.
- A full theme YAML loader (k9s skins). The 6-token palette is hardcoded in `lib/theme.sh`. Theming can come later.
- Bubble Tea rewrite. Stays bash.

## Design

### Component 1 — Semantic palette (`lib/theme.sh`)

Replace every existing color constant with these six tokens:

```
C_PRIMARY    standard text, list items, default border
C_ACCENT     selection background, active focus, links
C_MUTED      secondary metadata, dim hints, inactive border
C_SUCCESS    ok states (✓), validated session, healthy resource
C_WARN       mismatch (⚠), pending, attention
C_DANGER     errors (✗), expired, failed resource
```

Concrete ANSI values (true-color terminals):

| Token | FG hex | Notes |
|---|---|---|
| `C_PRIMARY` | `#e0e0e0` | near-white, default body |
| `C_ACCENT` | `#7aa2f7` | soft cyan-blue, selection highlight |
| `C_MUTED` | `#565f89` | grey-blue, secondary text |
| `C_SUCCESS` | `#9ece6a` | green |
| `C_WARN` | `#e0af68` | amber |
| `C_DANGER` | `#f7768e` | red-pink |

These are Tokyo Night palette values — high contrast on dark terminals, readable on light. Fall back to 16-color ANSI when `tput colors` reports < 256.

Old constants (`C_CYAN`, `C_CYAN_B`, `C_LCYAN`, `C_LBLUE`, `C_WHITE_B`, `C_RED`, `C_GREEN`, `C_YELLOW`, `C_DIM`) are deleted. Every existing usage gets mapped to one of the six. Style modifiers (`C_BOLD`, `C_RESET`) stay as separate constants.

`gum`'s widget styling is centralized via env vars exported in `lib/theme.sh`:

```bash
export GUM_CONFIRM_PROMPT_FOREGROUND="${C_PRIMARY}"
export GUM_CONFIRM_SELECTED_BACKGROUND="${C_ACCENT}"
export GUM_INPUT_CURSOR_FOREGROUND="${C_ACCENT}"
# ...
```

so every `gum confirm` / `gum input` call automatically follows the palette.

### Component 2 — Chrome layout

Three regions, fixed positions, drawn by `lib/ui.sh`:

```
row 1     ╭─ kubekit ─────────────────────────────────────────────────╮
row 2     │ k8s <ctx>  ns <ns>  aws <profile> <status-glyph> <detail>  │
row 3     │                                            R refresh        │
row 4     │                                            P profile        │
row 5     │                                            ? help           │
row 6     ╰────────────────────────────────────────────────────────────╯
row 7      <breadcrumb>          (e.g. "Main › Database")
row 8     <blank>
row 9-N   <content / picker>
row N+1   <blank>
row N+2    / filter   : command                       3 of 4   ↑↓ ⏎
```

- **Top border (row 1):** rounded `╭─ kubekit ─...─╮`, left label `kubekit` (no version — version lives in `--version`). Border color: `C_MUTED` baseline; switches to `C_ACCENT` when an action is in-flight (replaces the spinner pattern).
- **Status line (row 2):** k9s-style segments — `k8s <ctx>` + `ns <ns>` + `aws <profile> <glyph> <detail>`. Each segment prefixed with a 3-letter sigil (`k8s` / `ns` / `aws`) in `C_MUTED`, value in `C_PRIMARY`, status glyph in `C_SUCCESS` / `C_WARN` / `C_DANGER` per session state. Replaces the current footer's AWS segment.
- **Key hints (rows 3-5, right-aligned):** per-screen contextual keys. Each screen registers its hints via a new helper:

  ```bash
  set_keyhints "R refresh" "P profile" "? help"
  ```

  The header rebuilds on each `draw_chrome`. Max 5 hints per screen. Common keys (`q quit`, `esc back`) are not listed — assumed known. Hint format: `<key> <action>` separated by 2 spaces.
- **Bottom border (row 6):** mirror of top border.
- **Breadcrumb (row 7):** `Main › <Section> › <Sub>` in `C_MUTED`. Updated by `push_breadcrumb` / `pop_breadcrumb` helpers called from each menu entry. Replaces the per-screen `header "..."` text.
- **Content (rows 9 to N):** owned by the current screen.
- **Action bar (row N+2):** `/ filter   : command   ...   <position>   <local-key-hints>`. Position counter (`3 of 4`) is set by `choose_menu`. Local key hints are arrow + enter glyphs.

The header morphing icon (`ANIM_ICONS`, `ANIM_PHASE`, `_update_anim`) is removed entirely. `_tick()` no longer calls `_update_anim`.

Selection shimmer is **kept but redesigned** as a one-shot "selection confirmed" pulse:

- Fires **only when `sel` changes** (arrow keys, page up/down), not on a timer.
- Duration: ~150 ms total across 3 frames. Single left-to-right pass. No loop.
- Palette: `C_MUTED` → `C_ACCENT` → settle. No `C_WHITE_B` flash.
- Drawn as a brief overlay *on top of* the full-row reverse-video selection indicator, not as the indicator itself. If the user misses the pulse (e.g. window unfocused), the selection is still unambiguously marked by reverse-video.
- Zero idle motion: between keypresses the screen is completely static.

`SHIMMER_POS`, `SHIMMER_DIR`, `SHIMMER_WAIT`, and the `_shimmer_tick` continuous-loop driver are deleted. The new pulse is invoked directly by `choose_menu` after each successful arrow press via a `_shimmer_pulse <row> <text>` function.

### Component 3 — Unified picker (`choose_menu` evolution)

Current `choose_menu` (in `lib/ui.sh`) supports `label|description` rows, filter, shimmer-on-selection. v0.2 changes:

1. **Multi-column items.** New input format: `label|description|metadata`. The list renders three columns:
   - col 1: `▍ ` (selection bar, `C_ACCENT` when selected, blank when not) + label, `C_PRIMARY`.
   - col 2: description, `C_MUTED`, left-padded to align across rows.
   - col 3: metadata, `C_MUTED`, right-aligned.

   Existing 2-column callers (`label|description`) keep working — metadata column is omitted when not provided.

2. **Full-row reverse-video on selection.** The whole selected row gets reversed colors (`\033[7m`), not just the leading character. Drops the shimmer animation entirely.

3. **Position counter.** Returns `current of total` to the action bar via the global `PICKER_POSITION` string.

4. **Per-screen key hints.** Caller passes a hints array; `choose_menu` registers them with `set_keyhints` so the header reflects what `R`/`P`/etc. do in this picker.

5. **Custom keybindings.** Caller can pass a `--keybinding 'R:refresh'` style spec; the picker emits the bound action via stdout (separate from selection) and the caller dispatches.

Signature evolution:

```bash
choose_menu \
  --title "Database Tunnel" \
  --hint "R refresh" --hint "P profile" \
  --bind "r:refresh" --bind "p:profile" \
  -- \
  "Production Aurora|aurora-pg|prod" \
  "Staging Aurora|aurora-pg|stage" \
  "Custom endpoint…"
```

Return: `selection=<label>` or `action=<binding>` on a single line, parsed by callers.

### Component 4 — Replace `gum choose` / `gum filter` with `choose_menu`

Audit shows two flows using `gum`:
- `lib/db_forward.sh:db_forward` — `gum choose --header "  Database target"`. Replace.
- `lib/actions_aws.sh:switch_context` — `gum filter --placeholder ...`. Replace.
- `lib/actions_aws.sh:connect_cluster` — `gum filter --placeholder ...`. Replace.

`pick_aws_profile` (in `lib/pickers.sh`) and `pick_namespace` already use `choose_menu` — no change.

`gum confirm` (used by `aws_session_ensure`, `ensure_kube_context`) and `gum input` (none currently, future use) **stay**. They're modal and well-styled; no UX mismatch.

### Component 5 — Filter + command bar

Two modes share the action bar's leftmost segment:

- `/` keystroke → activates filter input. Prefix `/` shown. Live-filters the visible list. Esc cancels.
- `:` keystroke → activates command input. Prefix `:` shown. Enter executes the command (initial commands: `:q`, `:help`, `:profile <name>`, `:context <name>`, `:ns <name>`). Esc cancels.

Implementation:

- The action bar renders a fixed leftmost slot occupied by either `<empty>`, `/ <filter text>`, or `: <command text>`.
- When activated, `choose_menu` swaps that slot for a `read -r` input loop using ANSI cursor positioning. No new TUI engine needed.
- Command set is registered via a `register_command` helper; menu screens add their own.

### Component 6 — Focus / border color

- Idle border: `C_MUTED`.
- Active screen (the current `choose_menu`): `C_ACCENT` border.
- Background tasks running (e.g. discovery in progress): border switches to `C_WARN` briefly, then back.

Implementation: `draw_chrome` reads a global `CHROME_STATE=idle|active|busy` and selects the border color accordingly. The transitions are driven by `choose_menu` (sets `active` on entry, `idle` on return) and by `_discover_db_targets` etc. (sets `busy` while running).

### Component 7 — Help screen (`?`)

`?` from any screen overlays a help panel listing:

- Current screen's contextual keys (auto-derived from `set_keyhints` registrations).
- Global keys (`q quit`, `esc back`, `/ filter`, `: command`, `? help`).
- Active filter and last command (if any).

Implementation: a modal screen rendered inside the chrome with `C_PRIMARY` text on default background, dismissed by any key. Reuses the `clear_content` + `draw_chrome` pattern, no new infrastructure.

## Phased rollout

Each phase is a commit boundary and independently revertable.

| Phase | Files | Outcome |
|---|---|---|
| **2a** | `lib/theme.sh` (rewrite) + mechanical sed across `lib/*.sh` | All colors map to the 6-token palette. No visual change yet beyond color drift. |
| **2b** | `lib/ui.sh` (`_header_bar`, `_footer_bar`, `draw_chrome`, breadcrumb) | New chrome layout. Morphing icon and shimmer code deleted. |
| **2c** | `lib/ui.sh` (`choose_menu`), `lib/db_forward.sh`, `lib/actions_aws.sh` | Unified picker with metadata columns. `gum choose`/`gum filter` calls replaced. |
| **2d** | `lib/db_forward.sh` (R/P keybindings) + `lib/menus.sh` (`set_keyhints` per screen) | Contextual hints surface in header; refresh + profile-switch wired. |
| **3a** | `lib/ui.sh` (CHROME_STATE), all callers of `_redraw_footer` / `draw_chrome` | Border color signals idle/active/busy. |
| **3b** | `lib/ui.sh` (action bar input), new `lib/commands.sh` | `/` filter and `:` command bar. |
| **3c** | `lib/ui.sh` (help overlay) | `?` help screen. |

P2a–P2d together deliver the "looks like a real tool" win and can be merged independently of P3. P3 is the polish layer.

## Error handling

| Failure | Behavior |
|---|---|
| `tput colors` < 8 | Theme falls back to plain ANSI (no fg color, just bold/reverse for emphasis). |
| Terminal width < 80 | Header hides keyhints column, status line wraps. |
| `gum` not installed | `gum confirm` calls fall back to `read -p ... [y/N]`. Already the pattern in `aws_session_ensure`. |
| `kubectl` not installed | Existing behavior (footer shows `no cluster`). |

## Testing

Manual scenario matrix (no automated test framework in this codebase):

1. **Theme load:** `KUBEKIT_THEME=light ./kubekit.sh` — palette swaps cleanly (deferred; v0.2 ships dark only, no env var yet, but constants are isolated for it).
2. **Picker uniformity:** Main menu → Database menu → Switch Context → EKS Connect. Same selection indicator, same filter behavior, same keybindings throughout.
3. **Keyhints update per screen:** main menu shows different hints from DB menu shows different hints from pod list.
4. **Filter mode:** `/` activates input, types narrow the list, esc clears, enter on match selects.
5. **Command mode:** `:` activates input, `:ns kube-system` switches namespace, `:q` quits.
6. **Border color:** discovery in DB picker briefly turns border `C_WARN`, then back to `C_ACCENT`.
7. **Bash 3.2 + zsh test envs:** verify no associative arrays, no `${var,,}`, no `wait -n`.
8. **Help overlay:** `?` from each screen shows contextual + global keys.
9. **Narrow terminal:** resize to 70 cols, confirm wrapping behavior.

## Risks

- **Mechanical color rename touches every `lib/*.sh`.** Mitigated by doing it in one commit, easy to revert; the mapping is 1:1 (`C_CYAN` → `C_ACCENT`, `C_DIM` → `C_MUTED`, `C_RED` → `C_DANGER`, etc.).
- **`choose_menu` evolution risks regressing existing main-menu UX.** Mitigated by keeping the 2-column code path working — metadata column is optional.
- **Command bar adds non-trivial state.** Phase 3b is the smallest piece I'd cut if scope creeps.
- **Removing the animated icon may upset a user who likes it.** Worth it; "feels like a real tool" outranks novelty.

## Open questions

1. Should the breadcrumb show the kubectl context too (e.g. `production-eks › Main › Database`)? My recommendation: no, the header already shows `k8s <ctx>`. Breadcrumb stays purely navigational.
2. Should `:q` quit or go back? My recommendation: `:q` quits (k9s convention). `esc` goes back.
3. Should we ship a `--theme` flag in this phase? My recommendation: no — palette tokens are isolated in `lib/theme.sh`, theming can be a v0.3 feature.

## Out of scope, deferred to v0.3+

- YAML/JSON theme loader.
- Plugin system for custom commands.
- Multi-pane layouts (lazygit-style).
- Mouse support.
- Right-prompt (Starship-style stable info on the right edge).
